# Доступ к AI Manager из интернета (статический IP + HTTPS)

Публичный адрес: **https://iox-ai-manager.duckdns.org:8443** (DuckDNS → 91.247.207.130).
Внутри машины схема такая:

```
интернет → роутер (91.247.207.130) ──проброс 8443/8080──► 192.168.0.23
                                                           ├─ Caddy :8443/:8080 (авто-сертификат Let's Encrypt, DNS-01)
                                                           └─► 127.0.0.1:8000 (AI Manager)
```

Почему не стандартные 443/80: на этих внешних портах уже работают другие сервисы
(192.168.0.19, nginx). Проброс `manager` настроен как **внешний 8443 → внутренний 8443**
и **внешний 8080 → внутренний 8080**.

Поскольку Let's Encrypt проверяет домен только через порты 80/443, используется
**DNS-01 challenge**: Caddy сам пишет TXT-запись `_acme-challenge.iox-ai-manager.duckdns.org`
через API DuckDNS и продлевает сертификат (~каждые 60-90 дней, полностью автоматически).

Caddy — единственная точка входа снаружи. AI Manager по-прежнему виден только изнутри;
авторизация — `X-API-Password` / `Authorization: Bearer` (пароль из `.env`).

## Что настроено на машине

- [x] Caddy 2.11.9 со сборкой `caddy\duckdns_build.exe` (включён плагин `dns.providers.duckdns`)
- [x] `caddy\Caddyfile` — порты 8443/8080, DNS-01 через токен из `caddy\duckdns.token`
- [x] `caddy\run.bat` — запуск с авто-перезапуском и чтением токена из `duckdns.token`
- [x] `scripts\install_caddy_autostart.bat` — автозапуск при входе в Windows
- [x] `scripts\open_firewall_https.bat` — правила брандмауэра для 8443 и 8080
- [x] DNS: `iox-ai-manager.duckdns.org → 91.247.207.130` (проверено)

## Действия пользователя (один раз)

### 1. Токен DuckDNS — `caddy\duckdns.token`

Создайте файл `D:\projects\AI_Manager\caddy\duckdns.token` и вставьте в него токен API
DuckDNS (https://www.duckdns.org → Login → account → token). Без него сертификат не выпустится.
Файл уже добавлен в `.gitignore`? — **нет, добавьте строку `caddy/duckdns.token` в `.gitignore`**
или просто не коммитьте его.

### 2. Брандмауэр Windows

Запустите **от имени администратора**:

```bat
scripts\open_firewall_https.bat
```

### 3. Проброс портов на роутере (192.168.0.1)

Текущие правила (см. «Виртуальный сервер»):

| Правило | Внешний | Внутренний IP | Внутренний | Статус |
|---|---|---|---|---|
| site | 80 | 192.168.0.19 | 80 | чужой сервис — не трогать |
| site | 443 | 192.168.0.19 | 443 | чужой сервис — не трогать |
| manager | 8080 | 192.168.0.23 | 8080 | ✅ нужен (HTTP→HTTPS редирект) |
| manager | 8443 | 192.168.0.23 | 8443 | ✅ нужен (HTTPS) |

### 4. Автозапуск Caddy

```bat
scripts\install_caddy_autostart.bat
```
(тоже от имени администратора; создаёт задачу планировщика «AI-Manager-Caddy»)

### 5. Перезапуск AI Manager (для нового пароля)

Пароль в `.env` применяется только после перезапуска. Если есть идущие задачи — дождитесь:

```bat
scripts\restart.bat
```

### 6. Проверка

Сертификат выпустится автоматически после появления `duckdns.token` и перезапуска Caddy
(см. `caddy\caddy.log`). Проверьте из любой сети (например с телефона через LTE):

```bash
curl -H "X-API-Password: ваш_пароль" https://iox-ai-manager.duckdns.org:8443/api/models
curl -H "X-API-Password: ваш_пароль" https://iox-ai-manager.duckdns.org:8443/health
```

## Примечания

- **DuckDNS**: если белый IP когда-нибудь сменится, обновите запись на https://www.duckdns.org
  (поддомен `iox-ai-manager`). IP статический, менять не потребуется.
- **Проверка с самой машины** по `https://iox-ai-manager.duckdns.org:8443` может не работать
  (hairpin NAT у многих роутеров выключен) — это нормально; проверяйте с телефона/LTE.
- Порт 8000 наружу **не пробрасывайте** — снаружи должны быть открыты только 8443 и 8080.
- Сервис на 192.168.0.19 по-прежнему доступен на внешних 80/443 — конфликта нет.
